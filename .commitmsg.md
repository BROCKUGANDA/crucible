Retire the repair of the shared edge, now that this project has its own

`deploy/edge-attach.sh` and the `edge.yml` workflow existed to repair ONE
thing: the shared edge's hand-made attachment to this project's Docker
network. A recreate of that edge dropped the attachment, and every request
for this site answered 502 while every container here reported itself
healthy — the 2026-10-21 outage.

The repair was the right answer to the wrong question. It kept the coupling
alive: a script whose whole job was to attach an edge to a network it had no
business reaching, on a timer, forever. And a repair that outlives the fault
it repairs stops being a repair and becomes a way to re-create the coupling.

This project has its own edge now (`deploy/edge/`), on its own network, and
the shared edge is gone. So both the script and the workflow that installs it
are deleted rather than left running: an edge-attach timer that outlived its
fault would quietly re-attach a retired edge to this network on a schedule,
and nothing about that would look like a fault.

`compose.vps.yaml` describes the arrangement accurately now, which matters
because it is the file an operator reads to find out how the site is served.
