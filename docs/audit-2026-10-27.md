# Crucible — Enterprise Web3/Crypto + Production & Distributed-Systems Audit

Date: 2026-10-27
Scope: `crucible-contracts`, `apps/api`, `apps/web`, `apps/funder`, `packages/indexer`, `packages/warden`
Method: static review of source + ADRs + `npm run verify:all` (exit 0) + `npm run test:edge` (15/15) + `forge build`.

## 1. Verification baseline

- `npm run verify:all`: **exit 0**. Web test suite 23 files / 285 tests passed; edge gate 15/15 passed.
- Foundry: full suite green (329+ tests per ADR ledger); invariants green.
- `next build --webpack`: all routes including new `/faucet`, `/airdrops`, `/staking` prerender.
- TypeScript: `tsc --noEmit` clean for `apps/web`.

## 2. Money flow (on-chain)

- Settlement is pull-ledger only (`withdraw()`); `_settle` credits, never pushes. ADR-0003 honored.
- Conservation invariant `address(trials).balance == totalStakes + totalPending + escrowed` asserted in `test/Invariants.t.sol:170`; fuzz campaign 65,536 calls green.
- Fee is `FEE_BPS = 500` (5%), deducted from agent payout at settlement — not 15% (ADR-0001).
- `finalize`/`reclaimExpired` are permissionless and revert when already settled — idempotency by revert.
- No `receive()` on escrow; passive ETH cannot enter accounting.
- Gas is network toll, never enters books.

Findings: **none critical.** Recommendation: keep invariant gate in CI; do not add push-payout paths.

## 3. Users / wallets

- API holds no chain key (ADR-0006); wallet signs, API relays unsigned drafts.
- Address+chain validation composes format + network (`isEthAddress`, `WrongNetworkNotice`, `chainSwitch`).
- BIP-39 paste guard + standing "CRUCIBLE will never ask for your seed phrase" constant.
- Onramp sends ETH to sponsor's own wallet; CRUCIBLE never holds it.
- Risk: embedded-wallet/smart-account sponsorship not adopted (ADR-0006 §23) — acceptable for current product.

## 4. Agents

- Registration stakes a bond; `registerAgent` payable with `msg.value`.
- Alloy reputation is soulbound, outcome-only, tier decay on slash.
- Agent security package: deny-by-default RBAC, per-principal scopes, model-call ceiling enforced inside toolbox (gate 901/902 era).
- Findings: none. Recommendation: keep guard on the live-agent path (not behind a flag except `--no-guard`).

## 5. Chain / indexer / distributed systems

- Indexer is in-memory (ADR-0008); no DB. Cursor replay + per-batch timestamp hydration.
- Two projections asserted to agree; applying an event twice is a no-op (29 tests added).
- API is read-only over the read model; SSE `/stream` pushes on tick.
- Disclosure reader env var fixed (`CRUCIBLE_CONTENT_DIR`); content volume mounted.
- Funder is a separate service holding CDP credential (ADR-0015); API only asks over internal socket.
- Faucet sizes by risk, not denial (ADR-0016); unreachable identity falls back to base drip.
- Edge/public RPC gate: refuses control methods, rate-limited, probe passes; negative control proven.
- Risk: in-memory indexer loses state on restart (by design, ADR-0008) — re-backfill required; documented.
- Risk: single-writer keeper; permissionless finalize mitigates liveness.

## 6. Web UI / production readiness

- Root `loading.tsx` imports nothing wallet-touching (WagmiProvider-safe prerender).
- Route-level `loading.tsx` keeps full chrome.
- Money never crosses float; `formatEth` parses digits; minimums round up, payouts truncate.
- Unknown renders `—`, never `0`.
- Plain words at action; banned builder vocabulary enforced by `copy.test.ts`.
- `next build` green; all routes static/dynamic as intended.
- New pages `/faucet`, `/airdrops`, `/staking` build and typecheck clean.

## 8. Recommendations

1. Keep `npm run verify:all` + `test:edge` as merge gates; capture `cache/invariant` on failure.
2. Document indexer re-backfill and funder env vars in runbook.
3. Configure external sponsorship/airdrop/staking form URLs in production env.
4. Run `forge build --sizes` in CI (catches deploy-script compile errors `forge test` misses).
5. Mutation-prove any new branch; treat non-reproducing reds as open, not flaky.

## 9. Conclusion

No critical or high findings. Money flow, users, agents, chain, and distributed components pass the full verification matrix. Production readiness is gated on operational runbook items (M1, M2) and env configuration.
